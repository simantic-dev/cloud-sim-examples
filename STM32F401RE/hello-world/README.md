# Hello, world on an STM32F401RE

A small program for the STM32F401RE, the microcontroller on ST's
NUCLEO-F401RE board. It says "Hello, world!", then says how long it has
been running, once a second.

You build it on your computer with make, and run it with two API calls to
[Cloud Sim](https://simantic.com/cloud-sim), which simulates the chip in the
cloud, so you don't need a board. What the program sends over its serial
port comes back to your terminal, each line stamped with the simulated time
it was sent at:

```
[0.000304s] (UART2) Hello, world!
[1.002226s] (UART2) Running for 1 s
[2.004227s] (UART2) Running for 2 s
…
[9.018230s] (UART2) Running for 9 s
```

## What you need

- **The Arm GNU Toolchain**, the compiler that turns C into code for the
  chip (`arm-none-eabi-gcc`), **make**, which runs it, and **git**, which
  gets this project:
  - macOS, with [Homebrew](https://brew.sh): `brew install --cask gcc-arm-embedded`.
    make and git come with Apple's command line tools: `xcode-select --install`.
  - Ubuntu or Debian: `sudo apt install gcc-arm-none-eabi make git`
  - Windows: install [WSL](https://learn.microsoft.com/windows/wsl/install),
    then follow Ubuntu's line in its terminal.
  - Anywhere else: [Arm's downloads](https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads).

  `arm-none-eabi-gcc --version` shows it's ready.
- **curl**, which calls the API, and **jq**, which reads its answers:
  macOS has curl, and `brew install jq` adds jq; on Ubuntu, Debian or WSL,
  `sudo apt install curl jq`.
- **A Cloud Sim API key**: create one in your account's
  [API Settings](https://simantic.com/account/api), and set it in your
  terminal:

  ```
  export SIMANTIC_API_KEY=smtc_...
  ```

  It lasts until you close the terminal. To keep it, add that line to your
  shell's startup file (`~/.zshrc` on macOS, `~/.bashrc` on Linux).

## Build

Clone the repository, go to this folder, and build:

```
git clone https://github.com/simantic-dev/cloud-sim-examples.git
cd cloud-sim-examples/STM32F401RE/hello-world
make
```

make builds the program into `build/hello-world.elf`, the file the chip
runs.

## Run it on Cloud Sim

Start a run. It prints nothing once the run has started; if jq prints an
error instead, fix that before going on.

```
# Start a run: upload the ELF to a simulated STM32F401RE. The answer is
# the run, with its id; if the API refuses it, jq says why.
RUN_ID=$(curl -sS https://cloud.simantic.com/v1/runs \
  -H "Authorization: Bearer $SIMANTIC_API_KEY" \
  -F mcu=STM32F401RE \
  -F uart_encoding=ascii \
  -F firmware=@build/hello-world.elf | jq -er '.id // error(.error)')
```

Then wait for the run to end and print what it sent over UART:

```
# Its UART output, once the run has finished; until then the API answers 409.
until curl -sf https://cloud.simantic.com/v1/runs/$RUN_ID/output \
  -H "Authorization: Bearer $SIMANTIC_API_KEY"; do sleep 2; done
```

The first command uploads the ELF and starts a run on a simulated
STM32F401RE; the second waits for the run to end and prints what the program
sent over USART2. The run is also in your
[Cloud Sim history](https://simantic.com/dashboard/cloud-sim).

A run lasts 10 simulated seconds. Add `-F simulated_seconds=30` to the
first command for longer (up to 60). To run your own firmware, point
`firmware=@` at its ELF and set `mcu` to its chip. The
[API reference](https://cloud.simantic.com/v1/docs) has every option, and
calls to follow a run live.

## Make it yours

Your program is in `Core/Src/main.c`. Look for these comments:

- `/* USER CODE BEGIN 2 */`: code here runs once, when the chip starts.
  That's where it says hello.
- `/* USER CODE BEGIN 3 */`: code here runs over and over, forever. That's
  where it waits a second and prints the time.

Change a message, save, `make`, and run it again. `printf` works as it does on
your computer, and `HAL_Delay(ms)` waits. ST's HAL, the library behind
`HAL_` functions, is documented in its
[user manual (UM1725)](https://www.st.com/resource/en/user_manual/um1725-description-of-stm32f4-hal-and-lowlayer-drivers-stmicroelectronics.pdf).

Keep your code between a `USER CODE BEGIN` comment and its `USER CODE END`.
The rest of the file is generated by STM32CubeMX, which replaces it when the
project is generated again.

## The files

- `Core/Src/main.c`: your program, and the setup STM32CubeMX generated:
  the chip's clock (84 MHz) and USART2, its serial port
- `Core/Src/stm32f4xx_hal_msp.c`: USART2's pins, PA2 (TX) and PA3 (RX)
- `Core/Src/syscalls.c`: how `printf` reaches `__io_putchar` in `main.c`,
  which sends each character out of USART2
- `Core/Src/stm32f4xx_it.c`: the interrupt handlers, such as the 1 ms tick
  `HAL_Delay` counts
- `Drivers/`: ST's HAL and Arm's CMSIS, the libraries the code calls, with
  their licenses
- `startup_stm32f401xe.s`, `STM32F401xx_FLASH.ld`: how the chip starts, and
  where the program goes in its flash and RAM
- `Makefile`: the build
- `hello-world.ioc`: the STM32CubeMX project

## Add to it with STM32CubeMX

[STM32CubeMX](https://www.st.com/en/development-tools/stm32cubemx.html) is
ST's free tool for setting up the chip: which pins do what, its clock, and
peripherals such as timers, SPI and I2C. Open
`hello-world.ioc` in it, change what you need, and press
**Generate Code**. It rewrites the generated code, keeps yours between the
`USER CODE` comments, and adds what the new peripherals need to the
Makefile. The project is set up for STM32CubeMX 6.17 and the STM32CubeF4
1.28.3 package.

## On a real board

On a NUCLEO-F401RE, USART2 is the board's USB serial port. Plug the board
in, copy `build/hello-world.bin` to the USB drive it shows up as, and open
its serial port at 115200 baud, 8N1, in a terminal program
(`screen /dev/tty.usbmodem* 115200` on macOS) to see the same lines.
